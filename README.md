# سامانه مدیریت برگزاری ورکشاپ — نمونه اولیه قابل کلیک

نمونه اولیه رابط کاربری برای مدیریت عملیات یک ورکشاپ/همایش: ثبت‌نام، صندوق، کارت سینه،
پذیرایی، گواهی، اطلاعات پایه و گزارش‌ها.

این پروژه **دموی محصول** است، نه نسخه تولیدی: هیچ بک‌اند، دیتابیس یا احراز هویتی ندارد و
همه داده‌ها در `localStorage` مرورگر نگهداری می‌شود. هدف، نشان‌دادن جریان کار و تجربه
کاربری نهایی به کارفرما پیش از شروع پیاده‌سازی واقعی است.

## اجرا

```bash
pnpm install
pnpm dev        # http://localhost:5173
pnpm build      # خروجی تولید در dist/
pnpm preview
```

نیازمندی: Node.js 20+ و pnpm.

## پشته فنی

React 19 + TypeScript + Vite، Tailwind CSS v4، `lucide-react` برای آیکون‌ها،
`jsbarcode` برای بارکد کارت سینه، فونت وزیرمتن (بسته‌بندی‌شده، بدون CDN).

## داده نمونه

- ۵۴ ثبت‌نام، ۳ کارگاه، ۷ رده، ۳ وعده غذایی، ۴ اسپانسر و ۱۲۰ هدیه
- داده‌ها با PRNG قطعی ساخته می‌شوند؛ هر بار یکسان است
- کلید ذخیره‌سازی: `workshop-ops-demo-v3`
- دکمه **بازنشانی** در نوار بالا همه تغییرات را پاک و داده اولیه را بازمی‌سازد

## صفحه‌ها

| صفحه | چه چیزی را نشان می‌دهد |
| --- | --- |
| داشبورد | شاخص‌های کلیدی، روند درآمد و ثبت‌نام، ترکیب رده/جنسیت/تخصص، ظرفیت کارگاه‌ها، آخرین ثبت‌نام‌ها |
| فرم ثبت‌نام | ثبت چندمرحله‌ای با اعتبارسنجی کد ملی (چکسام)، انتخاب کارگاه با کنترل ظرفیت، غذا، هدیه و پرداخت؛ محاسبه زنده مبلغ |
| کارت سینه | جست‌وجو با کد ملی/نام، پیش‌نمایش کارت ۸۵×۵۵ با بارکد، چاپ و ثبت سابقه چاپ |
| صندوق و مدیریت مالی | جمع درآمد به تفکیک POS/نقد/کارت‌به‌کارت، گزارش روزانه، آخرین تراکنش‌ها، چاپ گزارش رسمی و CSV |
| کارگاه‌ها | کارت هر کارگاه با ظرفیت، ثبت‌نام و درصد تکمیل، افزودن/ویرایش، خروجی لیست |
| مدیریت غذا | «اسکن» با کد ملی یا موبایل، تأیید تحویل با ثبت ساعت، جلوگیری از تحویل تکراری، صف انتظار |
| صدور گواهی | جست‌وجو، پیش‌نمایش گواهی دوزبانه A4 افقی، صدور با ثبت تاریخ/ساعت، سابقه صدور |
| اطلاعات پایه | مشخصات رویداد، رده‌ها و هزینه‌ها، وعده‌های غذایی، پکیج هدیه، متن گواهی، اسپانسرها |
| گزارشات | تحلیل ثبت‌نام، درآمد، پذیرایی، کارت و گواهی + خلاصه مدیریتی قابل چاپ |

## چاپ

هر عملیات چاپ، برگه خودش را در یک پورتال روی `body` رندر می‌کند و اندازه کاغذ را هم
خودش اعلام می‌کند؛ بنابراین پنجره چاپ با اندازه درست باز می‌شود و صفحه‌بندی خراب نمی‌شود:

- **کارت سینه:** لیبل ۸۵×۵۵ میلی‌متر، یک صفحه
- **گواهی:** A4 افقی، یک صفحه
- **گزارش صندوق و خلاصه مدیریتی:** A4 عمودی، یک صفحه

برای چاپ دقیق رنگ‌ها و قاب‌ها، در پنجره چاپ گزینه **Background graphics** را فعال کنید.
پیش‌نمایش روی صفحه دقیقاً همان چیزی است که چاپ می‌شود.

## چه چیزی پیاده نشده است

- بک‌اند، دیتابیس و API واقعی (همه‌چیز در مرورگر است)
- ورود کاربر، نقش‌ها و سطح دسترسی
- اتصال واقعی به اسکنر بارکد، کارت‌خوان POS یا پیامک
- پرداخت آنلاین (در دمو فقط روش پرداخت انتخاب و ثبت می‌شود)
- خروجی Excel واقعی (فایل CSV با سازگاری اکسل صادر می‌شود)

## سناریوی پیشنهادی دمو (۵ دقیقه)

1. **داشبورد** — «مدیر در یک نگاه چه می‌بیند؟»
2. **فرم ثبت‌نام** — «تکمیل با داده نمونه» → ثبت‌نام و پرداخت → مودال موفقیت → انتقال خودکار به کارت سینه
3. **کارت سینه** — پیش‌نمایش کارت و چاپ آن؛ نمایش ثبت سابقه چاپ
4. **مدیریت غذا** — جست‌وجوی همان نفر، تأیید تحویل، سپس تکرار همان کد برای نمایش جلوگیری از تحویل دوباره
5. **صندوق** — جمع درآمد و گزارش تفکیکی، سپس «چاپ گزارش رسمی»
6. **صدور گواهی** — پیش‌نمایش گواهی دوزبانه و صدور آن
7. **گزارشات** — خلاصه مدیریتی و خروجی CSV
