# پیشنهاد اجرای سامانه مدیریت ورکشاپ

> این سند پیش‌نویس پیشنهاد است. بخش قیمت و زمان‌بندی باید پیش از ارسال توسط من تکمیل شود.

## ۱. خلاصه

سامانه‌ای تحت وب که کل چرخه برگزاری یک ورکشاپ را پوشش می‌دهد: ثبت‌نام و پرداخت، صدور کارت سینه،
کنترل پذیرایی، صدور گواهی و گزارش‌های مدیریتی. برای اینکه پیش از شروع کار، محصول دیده شود، یک
نمونه اولیه قابل کلیک از تمام صفحه‌ها آماده شده است؛ رابط کاربری نهایی همان چیزی است که در دمو
دیده می‌شود، فقط پشت آن یک بک‌اند واقعی قرار می‌گیرد.

## ۲. درکی که از نیاز پروژه دارم

بر اساس توضیحات پروژه، مهم‌ترین نیازها این‌هاست:

- ثبت‌نام و پرداخت در محل رویداد باید سریع باشد و صف ایجاد نکند؛
- کارت سینه باید همان لحظه چاپ شود و سابقه چاپ داشته باشد؛
- تحویل غذا باید یک‌بار باشد و قابل ردیابی؛
- گواهی باید بدون کار دستی و با نام دوزبانه صادر شود؛
- مدیریت باید در هر لحظه بداند چند نفر ثبت‌نام کرده‌اند، چقدر فروخته شده و چه چیزی تحویل داده شده است.

دموی آماده‌شده دقیقاً همین جریان‌ها را نشان می‌دهد، از جمله جلوگیری از تحویل دوباره غذا و
ثبت خودکار تاریخ چاپ کارت و صدور گواهی.

## ۳. نمونه اولیه

- **اجرا:** `pnpm install && pnpm dev`
- **داده:** ۵۴ ثبت‌نام نمونه، ۳ کارگاه، ۷ رده، ۳ وعده غذایی؛ دکمه «بازنشانی» داده اولیه را برمی‌گرداند.
- **صفحه‌ها:** داشبورد، ثبت‌نام، کارت سینه، صندوق، کارگاه‌ها، پذیرایی، گواهی، اطلاعات پایه، گزارش‌ها.
- **چاپ:** کارت ۸۵×۵۵ میلی‌متر، گواهی A4 افقی، گزارش‌های A4 — هر کدام یک صفحه، بدون تنظیم دستی کاغذ.
- **محدودیت:** داده‌ها در مرورگر ذخیره می‌شوند؛ بک‌اند، ورود کاربر و اتصال به دستگاه‌های واقعی ندارد.

## ۴. پیشنهاد فنی

**گزینه پیشنهادی: PHP 8.3 + Laravel + MySQL 8 + Livewire + Tailwind**

- با مهارت PHP که در آگهی آمده هم‌سو است و نگهداری‌اش برای تیم کارفرما ساده‌تر می‌ماند.
- رابط کاربری دمو تقریباً بدون تغییر با Blade و Livewire قابل پیاده‌سازی است؛ نیازی به دو تیم فرانت و بک نیست.
- چاپ کارت و گواهی سمت سرور با mPDF انجام می‌شود تا خروجی روی هر پرینتری یکسان باشد؛ بارکد با
  کتابخانه‌های PHP تولید و در صورت نیاز QR هم اضافه می‌شود.
- احراز هویت، نقش‌ها (مدیر رویداد، صندوقدار، مسئول پذیرایی) و گزارش‌ها با امکانات خود لاراول.

**گزینه جایگزین: React SPA + API**

اگر کارفرما بعداً بخواهد اپلیکیشن موبایل یا اسکن آفلاین داشته باشد، همین رابط به‌عنوان SPA روی
یک API لاراول سوار می‌شود. هزینه و زمان این گزینه بیشتر است، اما توسعه بعدی را ساده‌تر می‌کند.

**نکته عملی که پیشنهاد می‌کنم از ابتدا در نظر گرفته شود:** اینترنت سالن همایش همیشه پایدار نیست.
اگر پذیرایی و ثبت‌نام بخواهد حتی در قطعی اینترنت کار کند، فاز دوم باید شامل حالت آفلاین (PWA با
صف همگام‌سازی) یا یک کیوسک محلی باشد. تصمیم نهایی را با کارفرما می‌گیریم، اما معماری از روز اول
باید برای این حالت آماده باشد.

## ۵. محدوده فاز اول (نسخه قابل استفاده در رویداد)

| بخش | شامل |
| --- | --- |
| ثبت‌نام | فرم فارسی/انگلیسی، اعتبارسنجی کد ملی، انتخاب کارگاه با کنترل ظرفیت، غذا و هدیه، پرداخت نقدی/POS/کارت‌به‌کارت |
| صندوق | گزارش روزانه و تفکیکی، تطبیق با تراکنش‌ها، خروجی اکسل، گزارش رسمی قابل چاپ |
| کارت سینه | جست‌وجو با کد ملی یا اسکن، پیش‌نمایش، چاپ ۸۵×۵۵ با بارکد، سابقه چاپ |
| پذیرایی | تأیید تحویل با کد ملی/بارکد، ثبت ساعت، جلوگیری از تحویل تکراری، گزارش مصرف |
| گواهی | صدور دوزبانه A4 افقی با نام و تاریخ رسمی، سابقه صدور، چاپ مجدد |
| اطلاعات پایه | رویداد، رده‌ها و تعرفه‌ها، کارگاه‌ها، وعده‌ها، هدیه، متن گواهی، اسپانسرها |
| گزارش‌ها | داشبورد مدیریتی، درآمد، ترکیب شرکت‌کنندگان، عملکرد کارگاه‌ها، خروجی کامل اکسل |
| کاربران | ورود، نقش‌ها و سطح دسترسی، ثبت لاگ عملیات حساس |

## ۶. فاز دوم (اختیاری)

- اسکن آفلاین و همگام‌سازی خودکار
- پیامک تأیید ثبت‌نام و یادآوری
- درگاه پرداخت آنلاین
- چند رویداد هم‌زمان با داشبورد تجمیعی
- اپلیکیشن یا نسخه موبایلی برای مسئولان سالن

## ۷. زمان‌بندی پیشنهادی

| هفته | خروجی |
| --- | --- |
| ۱ | تحلیل نهایی، مدل داده، تأیید طرح صفحه‌ها |
| ۲ | ثبت‌نام، پرداخت، صندوق |
| ۳ | کارت سینه و چاپ، پذیرایی |
| ۴ | گواهی، اطلاعات پایه، گزارش‌ها |

جمعاً حدود **۵ هفته کاری** از زمان تأیید و دریافت داده‌های اولیه. این بازه با تعداد رویدادهای
هم‌زمان و نیاز به حالت آفلاین تغییر می‌کند.

## ۸. تحویل‌شدنی‌ها

- کد منبع کامل روی مخزن کارفرما
- مایگریشن‌ها و داده اولیه (رده‌ها، تعرفه‌ها، کارگاه‌ها)
- مستندات نصب، پشتیبان‌گیری و راهنمای اپراتور
- دو جلسه آموزش (مدیر سیستم و اپراتورهای روز رویداد)
- ۳۰ روز رفع نقص پس از تحویل

## ۹. سؤالاتی که پیش از قطعی‌شدن قیمت لازم است

1. در سال چند رویداد و چند رویداد هم‌زمان دارید؟
2. چند دستگاه چاپ لیبل و از چه مدلی استفاده می‌کنید؟
3. پیامک و درگاه پرداخت آنلاین لازم است یا پرداخت در محل کافی است؟
4. سرور و دامنه در اختیار کارفرماست یا تأمین آن با من است؟
5. داده‌های فعلی (اکسل یا سامانه قبلی) باید منتقل شود؟
6. لوگو و هویت بصری جدیدی هست یا همین طرح تأیید می‌شود؟
